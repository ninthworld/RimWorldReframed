## Evidence and acceptance rules

For a source-shown state, compare the original source crop at its measured scale and coordinates against a runtime capture using the same resolution, UI scale, scene and state. Preserve both raw images, renderer/build identity, screen origin, crop coordinates, and a fixed-coordinate difference. Do not resize or register the acceptance images to hide geometry differences. A transformed atlas may help diagnose a hypothesis, but it does not establish a match. Review structure, proportions, spacing, colors, shading, outlines, icon silhouettes, type metrics, wrapping, clipping and input-target placement; record remaining mismatches rather than calling a near match complete.

For a state absent from the artwork, use the inferred-design policy and inference register. Compare the implementation with its adopted extension specification and test its lifecycle, empty/error/overflow states. Passing an inferred-state review is not evidence that an unseen source screen was recovered.

Mark a project's visual status complete only after its source-shown states have reviewable matched-scale evidence and remaining discrepancies are accepted or resolved. Final acceptance additionally requires the functional, compatibility and persistence gates in the relevant work order and test regimen. Keep these outcomes independent in the register.
